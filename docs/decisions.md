# 決定事項

新しいものを上に追記する。

## 2026-10-31

### 技術構成は Vite + Svelte（TypeScriptなし）、保存は localStorage
- 理由：画面が小さく書け、後でスワイプやアニメを足しやすい。データは小さいので localStorage で足りる。1タスク1項目の形なので、IndexedDB への変更も作り直しにならない
- 却下：React（この規模には重め）／素のJS（画面が増えると管理がつらい）／IndexedDB（今は過剰）
- 見直す条件：データが増えて遅くなった時／ステップ6の同期時

### 保存形式はJSON。エクスポートは `tasks.json` 1ファイル（`version` つき）
- 理由：アプリが読み書きしやすく、9項目がそのまま入り、AIも読みやすい。1ファイルならエクスポートが簡単で、AIが1回で全体を読める
- 形：`{ "version": 1, "exportedAt": ISO日時, "tasks": [ ... ] }`。日時はISO文字列。値なしは `doneAt` が `null`、`nextAction`・`note` が空文字
- AIの読み方：エクスポートした `tasks.json` をClaude Codeに読ませる。受け渡しの詳細はステップ4で決める
- 却下：Markdown（9項目の構造化とアプリでの読み書きに向かない）／タスクごとの別ファイル（ステップ6の同期時に再検討）
- 見直す条件：ステップ6で同期を足すとき

### 1タスクの項目は9個：id・title・status・list・createdAt・doneAt・nextAction・updatedAt・note
- 理由：チェック丸と選択式の入力先が動く最小限に、AIが進捗を読むために必要なもの（doneAt・nextAction・updatedAt・note）を足した。doneAtは後から足すと過去分が空になるため最初から入れる
- 条件：statusは `open` / `done` の2値。入力先とプロジェクトは分けず、1つの `list`（既定 `inbox`）にまとめる
- 却下：「進行中」状態（欲しくなってから足す）／優先度・期限・タグ・サブタスク（要件にない）／未来への送り方・やる気ゼロの印（未決定。項目は後から足せる形にする）
- 見直す条件：使い始めて足りない項目が出た時

### データはブラウザ内に保存し、JSONエクスポートでAIに渡す。同期はステップ6で再検討する
- 理由：v1（ステップ4まで）はこれで足りる。GitHub同期は非公開リポジトリのトークン管理・同時編集の衝突・オフライン対応が要り、今は過剰
- 条件：後から同期を足しても作り直しにならないよう、1タスク＝1項目のJSONで持つ
- 却下：GitHubリポジトリ同期（手間が増える。ステップ6で再検討）／サーバー（運用の手間が大きい）
- 見直す条件：PCでも使いたくなった時（ステップ6）

### 共通設定の正本は `~/.claude/`。控えは `D:\User\Projects\claude-setup`（task-toolには置かない）
- 理由：スキル・フック等は全プロジェクト共通でtask-tool専用ではない。控えは復元・別PC用に残す
- 運用：`~/.claude/` を直したら、必要に応じて claude-setup 側にもコピーする。gitなし
- 却下：task-toolに置いたままにする（専用でない物が混ざる）／削除する（復元元がなくなる）

## 2026-10-30

### 寄り道はROADMAPに書き足して現在地を出し直す
- 理由：寄り道そのものより、ステップから外れて現在地が見えなくなることがやる気を削ぐため
- 見直す条件：保留が溜まりすぎたら整理する

### v1の完成ラインはステップ4（AI連携）まで
- 理由：「本当に必要？」と迷ったとき、v1に入っていなければ後回しにしてよいと判断できるようにする

### 1セッション＝ロードマップの1ステップ
- 理由：長いセッションでは前半の内容が薄れる。区切りがあるとやめどきもはっきりする
- 却下：完成まで1セッションで通す

### 進捗は「管理エージェント」ではなくファイルで管理する
- 理由：エージェントはセッションが変わると記憶が消える。ファイルならどのセッションからでも読める
- 却下：管理専用エージェントを常駐させる（必要になったら追加を検討）

### スキル・フックは最小限から始め、困ったら足す
- 理由：仕組みづくりが本題より大きくなるのを避ける
